# Lolly 1.0.9 build record

The pre-pressive one is being prepared from the main repository. [Release notes](1.0.9-draft.md) remain draft until publication. This record distinguishes building packages from publishing downloads or submitting them to stores.

## Build matrix

| Target | Artifacts | Build route |
|---|---|---|
| macOS Apple silicon | Application bundle, DMG | Local Developer ID build and notarisation |
| macOS Intel | Application bundle, DMG | `desktop-extra.yml`, Intel runner; distribution signing after collection |
| Windows x64 | NSIS EXE, MSI | `desktop-extra.yml`; unsigned installers |
| Linux x86_64 | DEB, AppImage, Flatpak | `flatpak.yml`, then `flatpak-smoke.yml` |
| Linux ARM64 | DEB | `linux-arm64.yml` |
| openSUSE Tumbleweed and Leap 16 x86_64 | Separate RPMs | `linux-rpm.yml` |
| Arch x86_64 | Pacman package | Repack the verified x86_64 DEB with `linux/arch/PKGBUILD` |
| Android ARM64 | Signed APK, AAB | Local SDK/NDK build using the existing release keystore |
| iOS ARM64 | Signed IPA | `ios-release.yml`, explicitly `upload=false` |
| Terminal | CLI/TUI package and native desktop sidecars | `publish-cli.yml` manual dispatch and each desktop build |

All app packages use version 1.0.9. The CLI package and engine retain their independent package versions. Public packages embed `lolly-start`; the private SUSE pack is excluded. Catalog signatures bind the exact target frontend.

## Reproduce

Install the root workspace and the selected Tauri shell's separate dependencies with `pnpm install --frozen-lockfile`. Set `LOLLY_PROFILE=lolly-start` and `LOLLY_EMBED_CATALOG=profile`. Supply `LOLLY_CATALOG_SIGNING_KEY` and `VITE_CATALOG_PUBLIC_KEY_JWK` from private credential storage.

Run `pnpm run build:desktop` on macOS, or `pnpm -C shells/tauri-mobile run tauri android build --target aarch64` for Android. Android signing uses the four `ANDROID_KEY_*` variables documented in [Build mobile](../docs/build-mobile.md). The desktop build includes the CLI and Quick Look extensions. Native runtime dependencies must match the target architecture.

Dispatch the named workflows from a fixed source ref. Download their artifacts only after successful completion, record the source commit and SHA-256 hashes, and test the packaged application. Store submission, npm publication and changes to the stable `lolly-latest.*` aliases are separate release actions.

## Verification record

Build results, checksums and platform checks will be recorded after the packages finish. A successful compiler or package job alone does not establish physical-device acceptance.
